## Standing rules for every node

1. **Test-first:** the invariant lands as a red test before the implementation.
2. **Green-CI before commit** (the hook enforces): `ruff check` + `ruff format --check` + `pyright`
   + `pytest -m "not gpu"`. GPU-marked tests run on this box when they exist — not deferred.
3. **Conventional commits**, one node per commit: `utils: add ZeRO-1 optimizer-state sharding`,
   `scaling: add IsoFLOP/Chinchilla fitter`, …
4. **Pull-rebase-push around every commit** (perf agents share this repo). Never edit their zone.
5. **Predict-before-run** wherever a number is measured; log predicted-vs-measured to
   `bench/RESULTS.md` (main-track section, additive).
6. **Docstrings carry intent + invariant + the interview question** (repo rule).
7. **Dependency policy:** heavy deps stay out of core `dependencies`; A4 extras live in the new
   `[project.optional-dependencies] data` group; tests `importorskip` so the CPU gate is hermetic.
8. **After each node:** tick the checkbox here, add the MASTERY_DEBT row, update STATUS if the
   assignment's % changed, push.

## Loop protocol

The session runs as a self-paced autonomous loop (`/loop` dynamic). Each wake-up: orient (`git log
--oneline -10`, this checklist) → execute the next node(s) via workflow orchestration → commit →
push → reschedule. Stop condition: W11 ticked, everything green, pushed. If blocked >2 attempts on
a node, mark it `[!] blocked: <reason>` here, move on, and surface the blocker in the end-of-turn
report.

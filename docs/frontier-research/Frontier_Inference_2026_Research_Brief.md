## The one-paragraph thesis

In 2026 the binding constraint of LLM inference has moved off FLOPs and onto **memory — KV-cache bytes, expert-weight residency, and HBM bandwidth** — and the workload has flipped to **decode-dominant, long-horizon, agentic, reasoning-heavy** traffic. The frontier is no longer a single fast kernel; it is the **co-design of engine + KV-cache substrate + SLO-aware router across a disaggregated cluster**. The single most valuable thing you can demonstrate is the ability to reproduce a *measured* win — a goodput crossover, a cache-hit-rate jump from 12% → 90%, a DeepSeek-class expert-parallel throughput number, or a hand-written kernel that beats the baseline on a Nsight roofline.

## 1. Serving systems & infrastructure

**The stack stratified into three layers:** engines (vLLM / SGLang / TensorRT-LLM) under an **SLO- and KV-aware control plane** (NVIDIA Dynamo / llm-d / K8s Gateway API Inference Extension), over a **cluster-wide KV-cache substrate** (Mooncake Store / LMCache). The highest-leverage optimizations migrated *up* from the kernel to the router.

**Frameworks now.** vLLM's **V1 engine** (default since mid-2025) re-architected around an isolated `EngineCore` process (ZeroMQ + msgpack) so tokenization/streaming overlap GPU work — solving the "CPU overhead dominates" problem (a Llama-8B forward on H100 is ~5 ms, so Python overhead was the bottleneck) — with a **unified token-budget scheduler** that erases the prefill/decode distinction and **zero-overhead prefix caching on by default**; ~1.7× throughput over V0, now ~v0.23 with async scheduler default ([vLLM V1](https://blog.vllm.ai/2025/01/27/v1-alpha-release.html)). vLLM joined the **PyTorch Foundation (May 2025)**. **SGLang** (RadixAttention; PyTorch ecosystem) is the prefix-caching/throughput leader, in production at **xAI, AMD, NVIDIA, LinkedIn, Cursor, Oracle, Baseten**, reportedly trillions of tokens/day, and is the leading open vehicle for large-scale DeepSeek serving ([SGLang](https://lmsys.org/blog/2024-01-17-sglang)). **TensorRT-LLM v1.0** promoted a **PyTorch backend to default**, cutting cold start ~28 min → 60–90 s. **NVIDIA Dynamo 1.0 went GA at GTC (March 2026)** — an engine-agnostic orchestration layer (disaggregated P/D pools, KV-aware router, tiered KV offload), reporting **>30× requests** on DeepSeek-R1 671B on GB200 NVL72 ([Dynamo](https://developer.nvidia.com/blog/introducing-nvidia-dynamo-a-low-latency-distributed-inference-framework-for-scaling-reasoning-ai-models/)). **Hugging Face TGI was archived (read-only) on March 21, 2026** — teach it as history; HF consolidated on vLLM/SGLang.

*Head-to-head rule:* unique-prompt batch → **TensorRT-LLM** (raw throughput/TTFT); mixed/fast-iteration/widest models → **vLLM**; prefix-heavy RAG/agents/multi-turn → **SGLang** (its edge balloons on shared prefixes); datacenter multi-node → **Dynamo over any engine**.

**Prefill–decode disaggregation is now the default playbook** (prefill is compute-bound, decode is bandwidth-bound; co-locating inflates decode TPOT 2–30×). Lineage: **DistServe** (OSDI 2024; 7.4× more requests *or* 12.6× tighter SLO), **Splitwise** (heterogeneous hardware — decode on cheaper GPUs), **Mooncake** (FAST 2025 **best paper**, KVCache-centric, in production for Kimi at >100B tokens/day). The KV mover is **NIXL** (non-contiguous RDMA/NVLink/NVMe; NCCL is contiguous-only and can't handle paged KV). The teachable cost: Llama-70B FP16 KV ≈ **320 KB/token**, so a 10k-token prompt moves **3.2 GB** (~250 ms over 100 Gbps). 2026 synthesis: **adaptive** disaggregation (per-request planners) and **attention–FFN disaggregation** (MegaScale-Infer, Step-3).

**KV cache became a managed, tiered, cluster-wide substrate.** **LMCache** (GPU→DRAM→SSD→Redis→S3) cuts TTFT 3.7–6.8× and is integrated into Dynamo 1.0. **KV-cache-aware routing** is the single highest-leverage production lever — *the router decides the hit rate, and the hit rate decides cost* (providers price cached tokens ~10× cheaper). llm-d on 16×H100/150 tenants: **P90 TTFT 0.5 s vs 90 s+ for random routing**, with **load-aware fallback** beating strict affinity on tail latency. **FP8 KV cache** is production-default (2× capacity). The vLLM × Mooncake Store integration on agentic Codex/SWE-bench traces hit **3.8× throughput, 46× lower P50 TTFT** by lifting cache hit rate **1.7% → 92.2%**. Agentic traces show **input:output ≈ 131:1** and **~94% inherently cacheable** — KV reuse across turns is the killer app.

**Large-scale MoE serving is *the* frontier systems problem.** DeepSeek-V3 (671B/37B, 256+1 experts, top-8, ~3% sparsity) forces a huge aggregate batch → experts spread across many GPUs (**expert parallelism**, all-to-all dispatch/combine). DeepSeek open-sourced the stack: **DeepEP** (FP8 all-to-all; ~153 GB/s intranode NVLink, ~45 GB/s internode RDMA on H800), **EPLB** (redundant-expert load balancer for hot experts), **DeepGEMM** (FP8 grouped GEMM, 1550 TFLOPS H800). Their published recipe on H800: **prefill EP32, decode EP144**, ~73.7k input / 14.8k output tok/s per node, *theoretical* 545% cost-profit margin. **SGLang reproduced this openly on 96×H100: 52.3k input + 22.3k output tok/s/node, ~$0.20 per 1M output tokens (≈1/5 the official API), 5× vs vanilla TP**; EPLB alone gave 1.49× prefill / 2.54× decode. On **GB200 NVL72 with NVFP4 MoE**, SGLang reached 26,156 input + 13,386 output tok/s/GPU (3.8× prefill, 4.8× decode vs H100).

**Production.** Autoscale on **queue depth / KV fill** (not GPU util) via KEDA. Cold start moved from 30–60 s to sub-5 s (Run:ai Model Streamer ~4.88 s; Modal GPU-memory snapshotting 70 s → 12 s). **S-LoRA** serves ~2,000 adapters (4× throughput) via unified paging. The gateway standardized: **K8s Gateway API Inference Extension** (`InferencePool` + Endpoint Picker doing KV-aware routing); **Istio 1.29 conformant (Feb 2026)**; GKE Inference Gateway "powered by llm-d." Guardrails run in-path (<50 ms/check). Serverless prices compressed hard (Llama-70B ~$0.88–0.90/1M tokens); **Baseten raised $300M at $5B (Jan 2026)** on 100× volume growth.

## 2. Algorithms & model-level efficiency

**Attention variants — the KV-reduction ladder.** GQA (8 KV heads per 64 query heads, G = H/4…H/8) is the de-facto baseline. **MLA** (DeepSeek V2→V3.2) low-rank-compresses K/V into one latent + a small decoupled-RoPE part, caching **~576 elements/token (~1,152 bytes), ~57× smaller than naive MHA**, *while improving quality*. **Sliding window + attention sinks** (Gemma 3 at 5:1 local:global with a 1024 window; GPT-OSS 128-token SWA) bound KV regardless of context. **Native Sparse Attention (NSA)** — DeepSeek, **ACL 2025 best paper** — is *training-native* and *hardware-aligned* (compressed + selected-block + sliding branches), up to **11.6× faster decode at 64K** at full-attention quality; it matured into **DeepSeek Sparse Attention (DSA)** in **V3.2-Exp (Sept 2025)**: a lightning indexer + **top-k=2,048 of 128K** drops cost to near-linear and **cut long-context API price ~50%**. **The biggest architectural shift of the year: linear/SSM hybrids crossed the quality bar.** The consensus efficient architecture is now *mostly-linear/SSM with a few global-attention layers* at 3:1–7:1 — **MiniMax-M1** (~25% of R1's FLOPs at 100K generation), **Qwen3-Next** (Gated DeltaNet 3:1, ~10× throughput at 32K+), **Kimi Linear** (first linear-hybrid to **beat** full attention under fair comparison; 75% KV reduction, ~6× decode at 1M), **Nemotron-H / Granite 4.0** (Mamba-2 hybrids, up to 3×).

**Attention kernels.** **FlashAttention-3** (Hopper: warp specialization, TMA, FP8) ≈ 740 TFLOP/s FP16 (~75% util), ~1.2 PFLOP/s FP8. **FlashAttention-4** (Blackwell, presented Hot Chips Aug 2025, written in **CuTeDSL**): a software exp2 on CUDA cores + ~10× fewer rescales, **~1,605 TFLOP/s on B200 (~71% util), 3.6× over FA2 — first attention kernel past a petaflop**. **FlashInfer** (UW+NVIDIA+CMU, **MLSys 2025 best paper**) is the unified block-sparse KV + JIT-compiled-variant engine that became the *de-facto backend* — the "default" is now **hardware-selected** (FA4 on Blackwell, FA3 on Hopper, FlashInfer/TRT-LLM kernels for FP4/MoE paths). **FlashMLA** (DeepSeek) hits ~3000 GB/s / 580 TFLOPS on H800 (~90% of peak) with paged KV.

**Quantization — FP8 is the baseline, FP4 is the frontier.** **NVFP4** (16-element blocks, FP8 E4M3 scale + FP32 tensor scale) has lower error than **MXFP4** (32-element blocks, E8M0 power-of-two scale); Blackwell-native FP4 is 2× FP8 / 4× BF16, reported "**same accuracy at 2.3× throughput vs FP8**." **GPT-OSS ships MXFP4** MoE weights (~4.25 bits → 120B on one 80GB H100). The deeper shift is **FP4 *training***: NVIDIA pretrained a 12B model on 10T tokens in NVFP4 within <1.5% of the FP8 loss; MLPerf Training v5.1 showed 3× faster time-to-train vs Hopper. Accuracy recovery is now via **quantization-aware distillation (QAD)**. Sub-4-bit hits a wall: ParetoQ found a **learning transition between 2 and 3 bits**; BitNet b1.58 works only when trained-from-scratch ternary. Tooling: **TensorRT Model Optimizer**, **llm-compressor** (v0.9.0 added MXFP4; NVFP4 Feb 2026). KV: KIVI 2-bit (3.47× throughput); MoE: per-expert sensitivity-aware (MxMoE).

**Speculative decoding is mainstream and lossless.** **EAGLE-3** (NeurIPS 2025) predicts tokens directly + fuses multi-layer features, unlocking a *scaling law* (more draft data → more speedup): **up to 6.5×**, acceptance 0.75–0.85, and it **sustains gains at higher batch** (peak ~batch 56). **MTP** (DeepSeek-V3's native module as drafter): >80% acceptance → ~1.8× at batch 1. vLLM V1 supports n-gram / EAGLE / EAGLE-3 / Medusa / MTP and **dropped the generic separate-draft-model path**. The 2026 twist is **parallel drafting — P-EAGLE** (all K draft tokens in one forward pass): **1.05–1.69× over EAGLE-3 on B200**, in vLLM since v0.16.0; **EAGLE 3.1** reports 2.03× at concurrency 1. Key nuance: gains **decay as batch fills** (compute-bound) but **recover under long context** (MagicDec) — exactly the reasoning regime.

**Test-time compute reshaped the economics.** Reasoning models emit **5K–50K sequential decode tokens** before answering — memory-bound, low-batch, KV-exploding. The hardware root cause: **DeepSeek-V3 needs an aggregate batch ≈18K tokens to become compute-bound on H100** — unreachable at reasoning's low batch — so reasoning runs deep in the bandwidth-bound region, making **speculative decoding the highest-ROI single-stream lever**. NVIDIA frames reasoning as **~100× more inference compute**; reasoning tokens are **billed though never shown**. "Overthinking" is now a recognized failure mode → adaptive/compute-optimal budgeting (s1 "budget forcing").

**Long context.** KV compression families: eviction (H2O, StreamingLLM sinks, SnapKV, PyramidKV — 2.2× throughput), low-rank (MLA), quantization (KIVI, TurboQuant). The 2025–26 shift is **reasoning-aware compression — R-KV** (NeurIPS 2025): **~100% of full-cache performance at 10% cache, 90% memory saved, 6.6× throughput**. Reality check: **RULER shows models reliably use only 50–65% of advertised context** ("context rot"). **RAG is not dead** — it's 8–82× cheaper for typical workloads; the consensus is hybrid/pragmatic.

## 3. Hardware & kernels

**The organizing law:** prefill is compute-bound (gated by FP8/FP4 tensor-core FLOPS); decode is memory-bandwidth-bound (gated by HBM TB/s, re-reading weights + KV every token). Every spec below reads through that split.

**NVIDIA roadmap.** **H100** (80 GB HBM3 @ **3.35 TB/s**, 989 dense FP16 / 1,979 FP8 TFLOPS, NVLink-4 900 GB/s) → **H200** (*same die*, 141 GB HBM3e @ **4.8 TB/s** — a pure decode/KV win, ~40% more decode throughput, zero prefill change: the cleanest demonstration that decode scales with bandwidth) → **Blackwell B200** (192 GB HBM3e @ **8 TB/s**, FP4 20 / FP8 10 / FP16 5 PFLOPS, NVLink-5 1.8 TB/s, 2nd-gen Transformer Engine with **FP4**) → **GB200 NVL72** (72 GPUs as one NVLink domain: 1.44 EFLOPS FP4, 13.4 TB HBM @ 576 TB/s aggregate, **130 TB/s NVSwitch fabric**, ~30× H100 — the *rack* becomes the unit of decode, so MoE all-to-all and giant shared KV stop being interconnect-bound) → **Blackwell Ultra GB300 NVL72** (H2 2025: **288 GB HBM3e/GPU**, +50% HBM aimed squarely at reasoning's bigger KV). **Grace** adds 480 GB LPDDR5X @ ~1 TB/s coherent over **NVLink-C2C 900 GB/s** — the structural enabler for KV offload. **Roadmap:** **Vera Rubin NVL144** (H2 2026: R200 with **288 GB HBM4 @ ~22 TB/s**, 50 PFLOPS NVFP4, NVLink-6 260 TB/s) and — the headline architectural move — **Rubin CPX** (end-2026: a **dedicated prefill GPU on cheap 128 GB GDDR7**, *no NVLink*, while HBM4 Rubin serves decode). NVIDIA is **physically splitting prefill from decode in silicon**. **Rubin Ultra NVL576 "Kyber"** (H2 2027: 15 EFLOPS FP4, **600 kW/rack**).

**Competitors split into three memory philosophies.** HBM-capacity maximizers (**AMD MI355X/CDNA4**: 288 GB HBM3e @ 8 TB/s, FP6/FP4, GA Oct 2025 — and **ROCm is now first-class in vLLM**; **Google TPU v7 "Ironwood"**: 192 GiB HBM3e @ 7.4 TB/s, inference-focused, 9,216-chip superpods; **AWS Trainium3**: 144 GB HBM3e @ 4.9 TB/s — Anthropic's **Project Rainier ≈ 500k Trainium2**). SRAM weight-stationary extremists (**Groq LPU**: 230 MB SRAM, no HBM, **80 TB/s** on-die, shards a 70B across ~576 chips; **Cerebras WSE-3**: 44 GB SRAM, 21 PB/s, ~2,100 tok/s on Llama-70B). Tiered hybrids (**SambaNova SN40L**: SRAM + HBM + DDR for cheap MoE expert residency).

**Roofline literacy is the core skill.** Per-token decode ≈ `2·P` FLOPs and ≈ `2·P` bytes (BF16) → **arithmetic intensity ≈ 1 FLOP/byte**, vs an H100 ridge point of ~295 (BF16) / ~591 (FP8) — decode sits ~150–600× below the ridge. Batch-1 ceiling: `peak_BW / (2·P_bytes)`; a 70B FP16 on one H100 ≈ **24 tok/s** upper bound. Batching raises AI ≈ linearly until you hit the ridge (then compute-bound) or run out of KV memory (the usual cap). **MBU** (achieved/peak bandwidth) is the decode metric; **MFU** the prefill metric.

**Kernel stack.** CUDA/PTX with Hopper (`wgmma`, **TMA**, warp specialization, thread-block clusters) and Blackwell (`tcgen05` MMA, **TMEM** 256 KB/SM accumulators, FP4 paths). **Triton** (block/tile DSL, the `torch.compile` backend, now with Blackwell support). **CUTLASS / CuTe** (Layout = Shape×Stride; CUTLASS 4.6 June 2026 with `tcgen05` block-scaled NVFP4, ~98% of peak, plus a Python **CuTe DSL**). **ThunderKittens** (Stanford tile DSL; TK 2.0 Jan 2026 adds Blackwell MXFP8/NVFP4). DeepSeek kernels: **DeepGEMM** (JIT FP8, 1,550 TFLOPS H800, ~2.7× expert-tuned CUTLASS) and **FlashMLA**. Cross-cutting: **PagedAttention** (KV waste 60–80% → <4%, 2–4× throughput), **Flash-Decoding** (KV-length parallel axis, up to 8× long-context), Stream-K GEMM, grouped GEMM + DeepEP for MoE, **Marlin/Machete** mixed-input quant kernels.

**Profiling loop.** **Nsight Systems** (system timeline — find the GPU-idle gap and the "many tiny kernels" launch-overhead pattern) → **Nsight Compute** (per-kernel **roofline chart**, memory-workload analysis, warp-stall sampling) → **torch.profiler / Kineto → Perfetto** + Holistic Trace Analysis (critical path: CPU- vs compute- vs comm-bound). The fix maps to the diagnosis: launch-bound → CUDA Graphs; memory-bound elementwise → kernel fusion; low AI → continuous batching; KV pressure → PagedAttention; memory wall → FP8/FP4; sequential depth → speculative decoding; cross-node MoE → comm/compute overlap (DualPipe).

**Roadmap forces:** HBM4 (JEDEC JESD270-4, April 2025; 2 TB/s/stack; 16-Hi mass production ~early 2027; Samsung HBM4E samples at 3.6 TB/s May 2026) remains *the* gating resource for decode; co-packaged optics (Quantum-X, Spectrum-X Photonics) enable multi-rack scale-out; the kernel future is **Python-first, tile-based, compiler-generated** (NVIDIA CUDA Tile / cuTile DSL; Triton on a CUDA Tile IR; Mojo/MAX as a CUDA alternative). Durable, hardware-independent skills: roofline reasoning, memory-hierarchy mastery, FP4 accuracy recovery.

**Sparsity is in steep monotonic decline:** Mixtral ~27% → Llama-4 Scout 15.6% → Qwen3-235B 9.4% → DeepSeek-V3 5.5% → Maverick 4.25% → **Kimi K2 3.1%** active. Kimi's "sparsity scaling laws" show loss keeps dropping as sparsity rises at fixed active params. The serving consequence: **sparsity cuts FLOPs but not VRAM** (all experts resident) — MoE serving is a distributed-systems problem (wide EP + PD disaggregation). **DeepSeek-R2 has not shipped as of June 2026; Llama-4 Behemoth was shelved** — treat both as rumor.

**Workload shifts that drive the curriculum:** (1) **reasoning** → decode-dominant, ~100× compute, KV grows with CoT length; (2) **agentic/long-horizon** → >95% prefix reuse, up to 1M-token traces, 100:1 input:output — **KV becomes a first-class persistent datastore**; caching is now a priced product (Anthropic/Gemini cache reads ~90% off), and on a real coding task enabling caching took cost **$1.35 → $0.54**; (3) **multimodal** → vision/video inflate token counts 1–3 orders of magnitude → **disaggregated Encode-Prefill-Decode** (landed in vLLM 0.11.1: up to 71% TTFT cut) + encoder caching; realtime voice imposes **sub-250 ms first-packet** SLOs (Qwen3-Omni Thinker-Talker 234 ms; gpt-realtime). **Emerging classes:** diffusion LLMs (Mercury 1,109 tok/s; Gemini Diffusion ~1,479; Seed Diffusion 2,146; Fast-dLLM up to 27.6× but bidirectional attention breaks naive KV cache — fixed by Block Diffusion); hybrid SSM (Falcon-Mamba constant memory; Jamba 4 GB KV @ 256K vs ~128 GB Llama-2); world models (Genie 3 at 24fps with a hard per-frame latency wall; Sora 2 per-second billing).

## 5. Talent signals & OSS targets

**Required floor (table stakes):** strong **C++ and Python**, computer-architecture + profiling fundamentals. **CUDA is gating, not preferred, for kernel roles.** Anthropic's *Performance Engineer, GPU* requires **CUDA, Triton, CUTLASS, FlashAttention, Nsight, NCCL/NVLink, INT8/FP8**. Hands-on **vLLM/SGLang/TensorRT-LLM** is near-mandatory at startups. Assumed-everywhere domain knowledge: KV-cache/PagedAttention, continuous batching, TP/PP/EP, speculative decoding, INT8/FP8/FP4; target hardware H100/H200/B200/GB200 with NVFP4 the frontier.

**Differentiating signals:** **OSS contributions to the serving stack are the single strongest differentiator** (NVIDIA "AI Inference Performance Engineer" roles work *directly inside vLLM*; Red Hat anchors vLLM). **Published beat-a-baseline benchmarks** ("3.3× faster than vLLM on H100") are a Baseten/Fireworks calling card. Published research is valued at Anthropic/SambaNova. Groq explicitly "skips the LeetCode grind."

**What interviews actually probe:** the signature round is **"make this kernel faster"** — Anthropic open-sourced its performance take-home (optimize a simulated-accelerator kernel using a hot-reloading Perfetto trace). Together gives 4–8h CUDA-kernel optimization take-homes. The canonical exercise is **naive matmul → cuBLAS** (coalescing → shared-memory tiling → vectorized loads → Tensor Cores/WGMMA; the siboehm worklog is the reference). **Roofline / arithmetic-intensity reasoning is ubiquitous** ("prefill = compute-bound, decode = memory-bound; compute the batch-size crossover"). Systems-design centers on serving stacks — Anthropic's most-reported prompt is **"design an inference batching system for one GPU"** (extending to KV eviction, paged attention, spec decoding, PD disaggregation). The field bifurcates into a **CUDA-kernel track** (NVIDIA, OpenAI, GPU startups, vLLM/Red Hat) and a **compiler/accelerator track** (Groq/Cerebras/SambaNova MLIR; DeepMind TPU + JAX/Pallas/Mosaic), with Anthropic straddling both.

**Best OSS to contribute to:** **vLLM** (flagship, ~2,000 contributors, but ~10 issues/day and a small reviewer pool → slow merges; RFC required for >500 LOC). **SGLang** (leaner queue → smarter *first-merge* target). **TensorRT-LLM** (DCO sign-off; heavier internal review). **FlashInfer** (the highest-leverage *kernel* repo to learn — NVIDIA now ships its top inference kernels into it; there's an **MLSys 2026 kernel-generation contest** as a structured on-ramp). Lowest barrier first PRs: **lm-eval-harness**, **llama.cpp**, **llm-compressor**. Universal rule: open an RFC first, back perf claims with reproducible benchmarks + tests, and **avoid docs/typo PRs as a credibility play**.

**Compute economics for the capstones:** stack free Colab (T4) + Kaggle (~30 hr/wk) ≈ 60 free GPU-hr/week (enough for C0–C3 at small scale); rent in short bursts for profiling/FP4/multi-GPU — Vast.ai H100 spot ~$1/hr, RunPod H100 ~$2–2.7/hr, B200 from ~$2.1/hr, Modal H100 ~$3.95/hr zero-idle. **The full ladder is doable for under ~$150** with disciplined spot/short-burst rental. Note **NVFP4 is Blackwell-exclusive** (B200/B300/RTX 5090) — H100/H200/A100 top out at FP8.

## 6. Future directions (2026 → 2028)

1. **Memory/bandwidth, not FLOPs, is the scaling axis.** Sub-quadratic attention (DSA-style learned sparsity, linear/full hybrids) becomes the *default*, not the exception; HBM capacity/bandwidth and EP all-to-all are the gating resources.
2. **Sparsity falls toward ~1–2% active**, making **wide EP + prefill/decode/encoder disaggregation across hundreds of GPUs** the default serving topology — and pushing disaggregation *finer* (attention–FFN split).
3. **KV becomes a managed storage tier** (cluster-wide pools, petabyte SSD/CXL tiers, GPUDirect/NIXL zero-copy); the open problem is a **standard cross-engine KV interchange format**. The economic unit shifts from **$/token to $/task with cache-hit-rate as the dominant lever**.
4. **Hardware co-designs around the prefill/decode split** (Rubin CPX = dedicated prefill silicon; decode-specialized accelerators); **FP4 becomes the default numeric format** for both inference and training, with QAD the standard accuracy-recovery recipe; sub-3-bit stays gated by the ParetoQ learning transition.
5. **Inference-time compute becomes adaptive and learned** — budget-aware effort control and model routers (GPT-5's router is the early signal) make *dynamic per-request compute* a scheduling problem the serving layer owns.
6. **New model classes pull serving toward streaming and hard latency walls** — diffusion LLMs (KV-caching solved via Block Diffusion) for high-throughput code/agent paths; hybrid-SSM for long-context/high-batch; realtime multimodal and world models making sub-250 ms first-packet and fixed per-frame budgets standard SLOs.
7. **Kernels go Python-first and compiler-generated** (tile IRs, autotuning, agentic kernel generation) — but roofline reasoning and memory-hierarchy mastery remain the durable human skills.

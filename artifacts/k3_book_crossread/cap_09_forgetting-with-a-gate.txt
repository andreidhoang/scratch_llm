KIMI DELTA ATTENTION
Forgetting, one channel at a time
YOUR GUIDE
Let's get started.

The delta rule we built in the previous chapter can correct a stored association, and that already separates it from plain linear attention. It still cannot do the other thing a bounded memory must do: let go of information that no longer matters. In this chapter we measure what that failure looks like over long streams of tokens, then fix it the way Kimi Delta Attention does — with a forget gate, a learned per-channel decay applied to the state at every step. The gate is the "gated" part of KDA's ancestry, and the reason a fixed-size state can face K3's 1M-token context window at all.

The plan mirrors the previous chapter: first the failure in numbers, then the one-line fix, then the parameterization K3 actually configures — including the gate_lower_bound: -5.0 entry that sits in the released config. As before we work with a single head and d_k = d_v = 4, using the delta_step and read functions we already wrote.

A memory with no exit

Recall the update. At step t the state S, of shape (d_v, d_k), receives a rank-1 correction:

S_t = S_{t-1} + beta_t * (v_t - S_{t-1} k_t) k_t^T

Every write goes in. Nothing ever comes out, except by being overwritten when a similar key recurs. The first question is what this does to the state over a long stream of unrelated tokens. The following experiment feeds 5,000 random unit-norm keys and random values through both the additive rule from two chapters ago and the delta rule, and tracks the Frobenius norm of the state:

import torch

torch.manual_seed(3)
d_k, d_v = 4, 4

def linear_attn_step(S, k, v):
    return S + torch.outer(v, k)

def delta_step(S, k, v, beta):
    return S + beta * torch.outer(v - S @ k, k)

def read(S, q):
    return S @ q

T = 5000
keys = torch.nn.functional.normalize(torch.randn(T, d_k), dim=-1)
vals = torch.randn(T, d_v)

S_lin = torch.zeros(d_v, d_k)
S_del = torch.zeros(d_v, d_k)
for t in range(T):
    S_lin = linear_attn_step(S_lin, keys[t], vals[t])
    S_del = delta_step(S_del, keys[t], vals[t], beta=1.0)
    if t + 1 in (1, 10, 100, 1000, 5000):
        print(f"t={t+1:<5}  ||S_lin|| = {S_lin.norm():7.2f}   ||S_del|| = {S_del.norm():.2f}")
t=1      ||S_lin|| =    2.55   ||S_del|| = 2.55
t=10     ||S_lin|| =    5.80   ||S_del|| = 3.92
t=100    ||S_lin|| =   26.14   ||S_del|| = 3.59
t=1000   ||S_lin|| =   75.94   ||S_del|| = 4.36
t=5000   ||S_lin|| =  137.45   ||S_del|| = 5.21

The additive state grows without limit — roughly like the square root of t, reaching 137.45 by five thousand tokens — because every outer product piles on top of the last. The delta state behaves differently: it climbs briefly and then hovers around 4 to 5 for the rest of the run. The error term subtracts as much as the value term adds once the state is full, so the norm self-limits.1
1 The plateau level is predictable: with unit keys and beta = 1, each write removes the state's existing answer along k and installs v there, so at equilibrium each of the d_k key directions holds roughly one value of typical norm E‖v‖ ≈ 2, giving a Frobenius norm near √(4·4) = 4.

That plateau looks like good behavior, and in one sense it is. In another sense it is the problem. A (4, 4) state has sixteen numbers; it can faithfully store about d_k = 4 associations, one per orthogonal key direction. Once the stream has supplied more than four distinct keys, every new write lands partly on top of old content, because random keys in four dimensions overlap substantially. The state is saturated: full to capacity, with each write purchased by damage to something older. We can watch the damage directly. Store one association, stream 500 unrelated tokens through the memory, and query the original key:

torch.manual_seed(3)
k1 = torch.tensor([1., 0., 0., 0.])
v1 = torch.tensor([2., 0., 0., 0.])

S = torch.zeros(d_v, d_k)
S = delta_step(S, k1, v1, beta=1.0)
print(read(S, k1))

keys = torch.nn.functional.normalize(torch.randn(500, d_k), dim=-1)
vals = torch.randn(500, d_v)
for t in range(500):
    S = delta_step(S, keys[t], vals[t], beta=1.0)
print(read(S, k1))
tensor([2., 0., 0., 0.])
tensor([-0.0075, -0.3207,  2.0597,  0.6272])

Immediately after the write, the memory returns v1 exactly. After 500 random writes it returns a vector whose largest component is in a channel v1 never touched. The stored fact was not preserved, and it was not cleanly removed either; it was churned into interference by hundreds of partial overwrites. A memory without forgetting does not keep old information. It converts old information into noise.

As the figure summarizes, the norm plateau and the recall failure are two views of the same saturation. Over K3's intended regime — sequences up to 1,048,576 tokens — a state that must carry every past write forever has no chance. The memory needs a policy for making room.

The fix: decay each key channel at its own rate

The fix used by KDA, following the gated linear-attention line of work, is to shrink the state slightly before every write.2
2 The direct ancestor is Gated DeltaNet (Yang et al., 2024), which added a learned decay to DeltaNet's delta-rule update. Mamba-2 and earlier gated linear attention used scalar or per-dimension decays on additive updates; KDA belongs to the delta-rule branch of this family.
 The update becomes

S_t = S_{t-1} diag(alpha_t) + beta_t * (v_t - S_{t-1} diag(alpha_t) k_t) k_t^T

where alpha_t is a vector of d_k numbers, each in (0, 1), produced from the current token by a learned projection. Because our state has shape (d_v, d_k), multiplying by diag(alpha_t) on the right scales column j of S by alpha_t[j]. Column j is exactly the memory's answer for the j-th key direction, so the gate gives every key channel its own forgetting rate, chosen token by token. This is the meaning of per-channel in KDA's per-channel forget gate: not one decay for the whole state, and not one per head, but one per key dimension.3
3 In the transposed (d_k, d_v) convention that some papers use, the same operation is diag(alpha_t) S, scaling rows instead of columns. As with the write rule in the previous chapter, only the bookkeeping changes.

In code the change is one line, since broadcasting alpha against S of shape (d_v, d_k) scales columns:

def gated_delta_step(S, k, v, beta, alpha):
    S = alpha * S                       # column j of S decays by alpha[j]
    return S + beta * torch.outer(v - S @ k, k)

Why per channel rather than one global decay? Different kinds of information live in different key subspaces after training, and they have different useful lifetimes. A channel that carries local syntactic state should forget within a few tokens; a channel that carries "which entity is this document about" should hold for thousands. A single decay rate would force one timescale on both. The next experiment makes the difference concrete. We store two facts in two different key channels, then stream 50 tokens of unrelated traffic whose keys live entirely in the other channels, so any fading we see comes from the gate alone rather than from overwriting:

torch.manual_seed(3)
e0 = torch.tensor([1., 0., 0., 0.])
e1 = torch.tensor([0., 1., 0., 0.])
v_a = torch.tensor([2., 0., 0., 0.])
v_b = torch.tensor([0., 2., 0., 0.])

traffic_k = torch.randn(50, d_k)
traffic_k[:, :2] = 0.0                  # keys orthogonal to e0 and e1
traffic_k = torch.nn.functional.normalize(traffic_k, dim=-1)
traffic_v = torch.randn(50, d_v)

alpha = torch.tensor([0.90, 0.999, 0.98, 0.98])
S = torch.zeros(d_v, d_k)
S = gated_delta_step(S, e0, v_a, beta=1.0, alpha=alpha)
S = gated_delta_step(S, e1, v_b, beta=1.0, alpha=alpha)
for t in range(50):
    S = gated_delta_step(S, traffic_k[t], traffic_v[t], beta=1.0, alpha=alpha)
    if t + 1 in (5, 20, 50):
        print(f"after {t+1:>2} more tokens: "
              f"read e0 -> {read(S, e0)[0]:.4f}   read e1 -> {read(S, e1)[1]:.4f}")
after  5 more tokens: read e0 -> 1.0629   read e1 -> 1.9900
after 20 more tokens: read e0 -> 0.2188   read e1 -> 1.9604
after 50 more tokens: read e0 -> 0.0093   read e1 -> 1.9024

Channel 0 was given alpha = 0.90 and its stored value melts away: from 2 down to 0.0093 after fifty tokens, matching the closed form 2 · 0.9^51 ≈ 0.0093 (the entry decays once during the second setup write and once per traffic token). Channel 1 was given alpha = 0.999 and still reads 1.9024, which is 2 · 0.999^50. Same state, same traffic, two different lifetimes. For contrast, rerunning the loop with the ungated delta_step returns read e0 -> 2.0 and read e1 -> 2.0 exactly, unchanged after all fifty tokens — the stale entry never fades, which is precisely the behavior we set out to remove.

The per-channel gate: with alpha = 0.90 a stored value fades within tens of tokens, while alpha = 0.999 preserves it.
Anatomy of the gated update: the decay is applied before the error is computed, so the write corrects the state the model will actually keep.

Note that the order of operations in the figure matters: the decay is applied first, and the prediction error is computed against the decayed state, so the write repairs exactly the memory that will persist. Note also that the gate and the delta correction solve different problems and both are needed. The correction handles keys that recur — it overwrites instead of accumulating. The gate handles keys that never recur — it drains them instead of letting them rot into interference. Together they turn S from a write-only tape into a working memory with both replacement and expiry.

The parameterization, and what gate_lower_bound: -5.0 is for

How does a network produce alpha_t? The released config gives one direct clue, the entry gate_lower_bound: -5.0, and the released weights give four more: every KDA layer carries tensors named f_a_proj, f_b_proj, A_log and dt_bias. A list of names is not a formula, and Moonshot has not published how those four combine into a decay. What follows is our teaching form, the parameterization we use in the miniature; a passage at the end of this section sets it beside what the checkpoint holds.

It is standard in gated linear attention to parameterize the decay in log space, because the quantity that accumulates over a sequence is a product of per-step gates, and products are best controlled as sums of logs. Our reading of the config entry is that the log-decay is a bounded function of the token, with -5.0 as its floor:

gate_lower_bound = -5.0
raw = torch.tensor([-4.0, 0.0, 4.0])
log_alpha = gate_lower_bound * torch.sigmoid(raw)
alpha = torch.exp(log_alpha)
print(log_alpha)
print(alpha)
tensor([-0.0899, -2.5000, -4.9101])
tensor([0.9140, 0.0821, 0.0074])

However the projection saturates, one step can remove at most about 99.3% of a channel's content, never all of it.

Why bound the floor at all? Two reasons. First, retention: without a floor, a confidently wrong gate could multiply a channel by a value indistinguishable from zero, deleting in one token everything that channel carried, with no way for later tokens to notice what was lost. The bound guarantees that even the most aggressive forget leaves a recoverable trace for a few steps. Second, trainability: d(exp(x))/dx = exp(x), so once log_alpha drifts deeply negative the gradient through the gate vanishes and the channel can get stuck fully-forgetting; clamping the range keeps the gate inside a region where gradients still flow. A floor of -5.0 is a soft statement that "forget almost everything this step" is allowed and "destroy the channel permanently" is not.4
4 A useful intuition for decay values is the half-life log(0.5) / log(alpha): at alpha = 0.999 a stored value halves every 693 steps, at 0.99 every 69 steps, and at 0.9 every 6.6 steps. The floor alpha = 0.0067 halves it in a small fraction of a single step — near-instant on the token scale, yet still not zero.

Our reading of gate_lower_bound: the log-decay is a sigmoid scaled by -5.0, so per-step decay can approach but never cross e^-5.

In the miniature, then, each KDA head will carry a projection that maps the 64-dimensional token vector to d_k = 16 raw scores per head, pushed through exactly this pipeline. That matches the pattern of beta from the previous chapter — a per-token, learned, bounded control signal — except beta controls write strength with one scalar per head while alpha controls forgetting with one value per key channel.

Set that against the real tensors. Enumerating the 497,220 tensors of the released checkpoint shows the forget gate in a KDA layer to be four objects rather than one. f_a_proj and f_b_proj are a low-rank pair: the raw gate score is produced by projecting the token down to a small rank and back up, not by the single full-width matrix our miniature uses. A_log and dt_bias are a decay parameterization in the Mamba style, a log-scale decay parameter together with a bias on the per-token step size. So K3 splits the work between stored parameters and a token-dependent term, where our gate computes alpha from the current token alone, and it factors a matrix we leave full — a difference invisible at width 64 and worth millions of parameters per layer at 7,168.5
5 The names are measured facts about the released weights; the arithmetic that joins A_log, dt_bias, f_a_proj, f_b_proj and gate_lower_bound into a single alpha is not published. We use the bounded-sigmoid form above because it reproduces the behavior this chapter measures out of parts the reader has already seen.

Scaling the picture up to K3

At full scale the released facts are: 69 of K3's 93 layers are KDA layers, each maintaining a d_k × d_v state per head, with the gate we just built deciding, per channel and per token, what survives. The per-head key and value dimensions inside KDA are not broken out in the public sources — the config's head_dim: 128 and 96 heads describe the attention stack broadly — so our miniature simply fixes d_k = d_v = 16 across 4 heads and says so. What the public numbers do make unambiguous is the pressure the gate is under. With max_position_embeddings at 1,048,576, a KDA state is asked to summarize up to a million tokens in a few thousand numbers per head. Our 4-dimensional experiment saturated at roughly 4 associations; no fixed state survives a million tokens without a policy for discarding, and the gate is that policy, learned end to end. Moonshot reports up to 6.3× faster decoding at million-token context for the resulting architecture, a number we will earn properly when we discuss chunking and inference at the end of this part.

Two ingredients are still missing before we can assemble the full layer. The projections that produce q and k in a real KDA layer do not feed the recurrence raw: K3 first applies a short convolution over the last four tokens, a Swish activation, and the L2 normalization we have been using on keys since the previous chapter. The next chapter builds that pre-processing pipeline and shows what each stage buys. After that, we will be ready to wire projections, convolution, gate, and recurrence into a single nn.Module with the same interface as standard attention.

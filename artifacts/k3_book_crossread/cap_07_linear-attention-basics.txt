FOUNDATIONS
Linear attention: the state view
YOUR GUIDE
Let's get started.

The previous chapter ended with an accusation: standard attention keeps everything, and keeping everything at a million tokens costs terabytes of cache and exaFLOPs of score arithmetic. In this chapter we do something about it. With one substitution in the attention formula, the entire past compresses into a single small matrix — a running state that is updated once per token and read once per token, whose size never grows no matter how long the sequence runs. This idea, linear attention, is the foundation that 69 of Kimi K3's 93 layers stand on, and understanding both its arithmetic and its failure mode is the entry ticket to Part 02.

A scope note: we work with a single head, toy dimensions, and a plain Python loop, exactly as the delta-rule chapter that follows this one does. No gating, no forgetting, no chunked training form — those belong to later chapters. Here we derive the state view, implement it, verify it against softmax attention where the two should agree, price it, and then watch it fail at retrieval in a way softmax attention does not.

One substitution

Write down what causal softmax attention computes for position t, ignoring the 1/√d scale for a moment. The output is a weighted average of past values, with weights proportional to exponentiated query-key dot products:

o_t = sum_i exp(q_t · k_i) v_i   /   sum_i exp(q_t · k_i)        (i ≤ t)

The expensive part is structural: exp(q_t · k_i) couples the query to each key inside an exponential, so nothing can be precomputed about the keys independently of the query. Every new query must revisit every old key. That coupling is the whole reason the cache must keep every key and value forever.

The substitution: replace exp(q · k) with a product of feature maps, phi(q) · phi(k), where phi is some elementwise function applied to each vector separately.1
1 This is the move made by Katharopoulos et al. (2020) in "Transformers are RNNs", the paper that established the modern linear-attention framing. The feature map there, and here, is elu(x) + 1; richer choices (random features approximating the true exponential kernel, learned maps) form a family, but the factorization trick is identical for all of them.
 Once the query and key separate, the sums regroup:

o_t = sum_i (phi(q_t) · phi(k_i)) v_i / sum_i (phi(q_t) · phi(k_i))
    = S_t phi(q_t) / (z_t · phi(q_t))

where  S_t = sum_i v_i phi(k_i)^T      (a d_v × d_k matrix)
       z_t = sum_i phi(k_i)            (a d_k vector)

The query has been factored out of the sum. Everything the past contributes now lives in two accumulators: the matrix S, a sum of outer products v_i phi(k_i)^T, and the normalizer z, a sum of feature-mapped keys.2
2 We store S as (d_v, d_k) so the write is the outer product v phi(k)^T and the read is the matrix-vector product S phi(q). Kimi's materials describe KDA's per-head state as d_k × d_v — the transpose of the same object. The content is identical; we pick the orientation that makes the code read cleanly, and the next chapter keeps it.
 Both accumulators update by simple addition when token t+1 arrives, and neither grows: S is d_v × d_k at token three and d_v × d_k at token three million. Attention has become a recurrence — a write into a fixed-size memory, then a read from it. The figure below traces the derivation step by step.

One substitution, then algebra: with the query factored out, all past keys and values collapse into a fixed-size state S and normalizer z.

One requirement on phi deserves a sentence before we code it. Attention weights must be non-negative and must sum to one, so phi(q) · phi(k) has to be positive for the division to behave. The standard choice elu(x) + 1 maps every real number to a positive value, which guarantees this — and, as we will see shortly, that same guaranteed positivity is where the trouble starts.

Implementing both, side by side

Concept first: per token, the linear-attention loop does a write (add v phi(k)^T into S, add phi(k) into z) and a read (multiply S by phi(q), divide by the normalizer). The softmax loop, for comparison, scores the current query against every past key and averages. We implement both in the most literal loop form, at d_k = d_v = 4 so every tensor is printable:

import torch
import torch.nn.functional as F

torch.manual_seed(3)

def phi(x):
    return F.elu(x) + 1.0            # positive feature map

def softmax_attention(q, k, v):      # causal, single head, loop form
    T = q.shape[0]
    outs = []
    for t in range(T):
        scores = k[: t + 1] @ q[t] / q.shape[-1] ** 0.5
        w = torch.softmax(scores, dim=0)
        outs.append(w @ v[: t + 1])
    return torch.stack(outs)

def linear_attention(q, k, v):       # causal, single head, loop form
    d_k, d_v = k.shape[-1], v.shape[-1]
    S = torch.zeros(d_v, d_k)        # running state
    z = torch.zeros(d_k)             # running normalizer
    outs = []
    for t in range(q.shape[0]):
        fk, fq = phi(k[t]), phi(q[t])
        S = S + torch.outer(v[t], fk)          # write: v phi(k)^T
        z = z + fk
        outs.append((S @ fq) / (z @ fq))       # read: S phi(q), normalized
    return torch.stack(outs)

Note the shapes of what persists between iterations. The softmax loop's slice k[: t + 1] is the KV cache from last chapter, growing by one row per token. The linear loop carries only S and z — twenty numbers, total, at these dimensions. Causality costs nothing extra: because S is built left to right, position t's read can only see writes from positions up to t. Below is a visualization of one pass through the loop body.

The per-token loop: feature-map the key and query, write an outer product into the fixed-size state, read it back with the query, normalize by z.

Now both on the same toy sequence:

T, d_k, d_v = 6, 4, 4
q = torch.randn(T, d_k)
k = torch.randn(T, d_k)
v = torch.randn(T, d_v)

out_soft = softmax_attention(q, k, v)
out_lin = linear_attention(q, k, v)
print(out_soft.shape, out_lin.shape)
print(torch.allclose(out_soft[0], out_lin[0], atol=1e-6))
print((out_soft - out_lin).abs().mean().item())
print(F.cosine_similarity(out_soft, out_lin, dim=-1))

Three observations. The interfaces match: sequences in, same-shaped sequences out. At position 0 the outputs are exactly equal — with only one token in view, both methods can only return v[0], and the check confirms it to six decimal places. From position 1 onward the outputs diverge (mean absolute difference about 0.071, cosine similarities between 0.97 and 1.0), because phi(q) · phi(k) is a different similarity function than exp(q · k). Linear attention is not an approximation of softmax attention that gets better with effort; it is a different layer that happens to share the interface. On random inputs the two track each other loosely. The interesting question is where they part company, and for that we need a task with structure.

The price, precisely

Before the failure, the payoff. We can count multiplications for both loops exactly — per token, softmax attention scores against t keys and averages t values, while linear attention does one outer product, one matrix-vector read, and the normalizer bookkeeping, independent of t:

d_k = d_v = 4

for T in [256, 1024, 4096]:
    # softmax: at step t, scores against t keys plus a weighted sum of t values
    soft_mults = sum(t * d_k + t * d_v for t in range(1, T + 1))
    soft_mem = T * (d_k + d_v)                     # every key and value kept
    # linear: outer product write + state read + normalizer, per token
    lin_mults = T * (2 * d_k * d_v + 2 * d_k)
    lin_mem = d_v * d_k + d_k                      # S and z, regardless of T
    print(f"T={T:>5}: softmax {soft_mults:>12,} mults, {soft_mem:>6} floats kept | "
          f"linear {lin_mults:>9,} mults, {lin_mem} floats kept")
T=  256: softmax      263,168 mults,   2048 floats kept | linear    10,240 mults, 20 floats kept
T= 1024: softmax    4,198,400 mults,   8192 floats kept | linear    40,960 mults, 20 floats kept
T= 4096: softmax   67,125,248 mults,  32768 floats kept | linear   163,840 mults, 20 floats kept

The columns tell the two stories from last chapter, resolved. Compute: softmax multiplications grow quadratically (quadrupling per doubling of T), linear attention's grow linearly — at T = 4096 the gap is already 410×. Memory: the softmax column is the KV cache, 8 floats per token forever; the linear column is pinned at 20 floats whether the sequence has a hundred tokens or a billion.

Scaled to K3, this is the arithmetic that makes million-token contexts survivable. Each of K3's 69 KDA layers maintains a recurrent state per head instead of a cache. The released config does not break out the KDA state's exact per-head dimensions, so as a labeled illustration take a 128 × 128 state per head: 96 heads × 128 × 128 × 2 bytes ≈ 3 MiB per layer, about 207 MiB across all 69 layers — constant, versus the 4,793.2 GB the dense cache from last chapter reaches at 1M tokens. Numbers of that shape are why Moonshot reports up to 6.3× faster decoding at million-token context. The figure below contrasts the two memory profiles over time.

Where the state view fails

If linear attention were simply cheaper, K3 would use it in all 93 layers and this book would be shorter. It is cheaper and worse, in a specific, demonstrable way: the fixed-size state cannot retrieve stored information cleanly, even when it has plenty of room.

The experiment: store four key-value pairs, using four well-separated keys (scaled orthogonal unit vectors — as distinguishable as keys can be) and four distinct values. Then probe with the first key and see what comes back. Softmax attention first:

keys = 3.0 * torch.eye(4)          # four well-separated keys
vals = 10.0 * torch.eye(4)         # four distinct values
query = keys[0]                    # ask for pair 0

w = torch.softmax(keys @ query / 4 ** 0.5, dim=0)
print("softmax weights:", w)
print("softmax answer :", w @ vals)
softmax weights: tensor([0.9677, 0.0108, 0.0108, 0.0108])
softmax answer : tensor([9.6775, 0.1075, 0.1075, 0.1075])

The softmax concentrates 96.8% of the weight on the matching key, and the answer is a clean copy of the stored value, 9.68 out of 10 in the right coordinate with 1% leakage elsewhere. Sharper keys would push it arbitrarily close to exact. This is attention doing what it is best at: lookup.

Now the same four pairs written into a linear-attention state, probed with the same query:

S = torch.zeros(4, 4)
z = torch.zeros(4)
for i in range(4):
    S = S + torch.outer(vals[i], phi(keys[i]))
    z = z + phi(keys[i])
fq = phi(query)
print("linear answer  :", (S @ fq) / (z @ fq))
linear answer  : tensor([3.8776, 2.0408, 2.0408, 2.0408])

The correct coordinate gets 3.88; each of the three wrong coordinates gets 2.04. The stored values were 10 and 0. The read is not a lookup but a mush — more than half the answer's mass lands off-target, for keys that could not have been more distinguishable. The figure below puts the two reads side by side.

The same four stored pairs, two reads: softmax retrieves nearly exactly, while the linear-attention state returns a mixture even for perfectly separated keys.

The cause sits in the feature map we were forced to choose. Positivity was required for the normalizer to behave; positivity also means phi maps every key into the all-positive orthant, where nothing is orthogonal to anything — elu(0) + 1 = 1, so even a key's zero coordinates contribute weight to every read. Softmax's exponential suppresses non-matching keys multiplicatively; the state's dot-product read has no suppression mechanism at all. Every stored pair leaks into every retrieval. This is retrieval interference, and it compounds: the longer the sequence, the more writes are superimposed in S, and the muddier each read becomes.

The running-memory framing, and what comes next

Here is the reframing that the rest of Part 02 builds on. Stop thinking of linear attention as "cheap attention" and think of S as a memory: the write S = S + v phi(k)^T stores an association from key to value, and the read S phi(q) retrieves against a query. Per head we carry a (d_v, d_k) matrix, updated once per token, read once per token — that object, in exactly this orientation, is what the next chapter picks up.3
3 The normalizer z is a softmax inheritance, and this is the last chapter in which it appears: the delta-rule layer ahead drops the division and instead controls the state's scale directly, through L2-normalized keys and bounded write strengths. Watch for the disappearance — it simplifies every equation that follows.

Seen as a memory, our experiment says the read is blurry. However, the deeper defect is in the write. S = S + v phi(k)^T adds unconditionally — it never looks at what S already contains. It cannot notice that a key is already occupied, cannot moderate a redundant write, cannot revise anything it stored before. Every failure we measured traces back to that blindness, and no feature map can fix it, because the problem is not how keys are represented but that the write policy ignores the memory's current contents.

The fix is a different write rule — one line changed in the loop you just built — and it comes from a surprising direction: a 1960s idea about training adaptive filters, applied inside the forward pass. That is the delta rule, the "Delta" in Kimi Delta Attention, and it is the subject of the next chapter.

A standard transformer block, as our baseline
YOUR GUIDE
Let's get started.

Kimi K3 is best understood as a stack of substitutions. Take the standard transformer block, swap its attention for Kimi Delta Attention in 69 layers and Gated MLA in 24, swap its MLP for a mixture of 896 experts in 92 of 93 layers, and add a cross-depth pathway; what remains — the residual wiring, the RMSNorm, the overall shape of the computation — is unchanged from the transformer everyone already knows. That makes the standard block the measuring stick for this entire book. Every later chapter will say "compared to the baseline, this component changes X", so in this chapter we build the baseline: causal multi-head attention, an MLP, RMSNorm, and pre-norm residual connections, in about eighty lines of PyTorch at our mini-K3 dimensions.

This is a refresher chapter, and we keep it brisk. If any piece here feels unfamiliar rather than half-remembered, the right move is a slower treatment — Sebastian Raschka's Build a Large Language Model (From Scratch) constructs each of these components over several chapters, and this book assumes roughly that level of preparation.1
1 Raschka's book builds GPT-2 from scratch, which uses LayerNorm and GELU where we use RMSNorm and (later) gated activations. The architectural skeleton — pre-norm blocks, causal attention, residual streams — is the same one K3 inherits.
 Our job here is narrower: fix the reference implementation, fix the shapes, and verify a forward pass.

The block at a glance

A transformer block takes a (B, T, d_model) tensor — batch, sequence length, model width — and returns a tensor of the same shape. Inside, two sublayers do the work. Attention mixes information across positions: token 7 can read from tokens 0 through 7. The MLP (also called the feed-forward network) transforms each position independently: no information crosses between tokens. Each sublayer is wrapped in the same pattern: normalize the input, apply the sublayer, add the result back to what came in.

The pre-norm block: each sublayer reads a normalized copy of the stream and writes its result back by addition.

Note the wiring in the figure: normalization sits inside each branch, before the sublayer, and the residual path runs uninterrupted from input to output. This is the pre-norm arrangement, and it is what K3 uses. The alternative, post-norm, normalizes after the addition, which places every layer's normalization directly on the residual path and makes very deep stacks harder to train. At 93 layers, K3 has a strong interest in the version where the stream flows through untouched.

RMSNorm

RMSNorm (root-mean-square normalization) rescales each token's vector to a fixed magnitude, then multiplies by a learned per-channel weight. Unlike LayerNorm it does not subtract the mean — it only divides by the root mean square of the entries.2
2 RMSNorm comes from Zhang and Sennrich (2019), who observed that LayerNorm's re-centering could be dropped with no quality loss, saving a reduction pass. Nearly every large model of K3's generation has adopted it.
 K3's config sets rms_norm_eps to 1e-5, the small constant that keeps the division safe when a vector is nearly zero, and we use the same value:

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(3)

class RMSNorm(nn.Module):
    def __init__(self, d_model, eps=1e-5):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(d_model))

    def forward(self, x):
        rms = torch.sqrt(x.pow(2).mean(dim=-1, keepdim=True) + self.eps)
        return self.weight * (x / rms)

Four lines of computation: square, mean, square root, divide, then the learned elementwise scale. To confirm it does what we claim, we feed it vectors with large and uneven magnitudes and measure the RMS before and after:

norm = RMSNorm(64)
x = torch.randn(1, 3, 64) * 10.0
y = norm(x)
print(x.pow(2).mean(dim=-1).sqrt())   # RMS before
print(y.pow(2).mean(dim=-1).sqrt())   # RMS after
tensor([[ 9.5544,  9.3143, 11.0602]])
tensor([[1.0000, 1.0000, 1.0000]], grad_fn=<SqrtBackward0>)

Three tokens arrive with RMS between 9.3 and 11.1 and leave with RMS 1.0 exactly (the learned weight is initialized to ones, so at initialization the norm is pure rescaling). This is the function of the layer: whatever magnitudes the residual stream accumulates across 93 layers of additions, each sublayer receives inputs at a standard scale. Causal multi-head attention

Attention lets each position build its output as a weighted average of value vectors, with weights computed by comparing its query against every key. Causal masking restricts the comparison to current and earlier positions, which is what makes the model usable for left-to-right generation. Multi-head means the comparison happens in several independent low-dimensional subspaces: our miniature splits d_model = 64 into 4 heads of 16 dimensions each, mirroring K3's 96 heads of 128 dimensions.3
3 In K3 the head arithmetic has a wrinkle worth noticing: 96 heads × 128 dims = 12,288, which is larger than the hidden size of 7,168. The attention projections widen the representation and the output projection brings it back down. Our miniature keeps the simpler textbook case where heads exactly tile the model width: 4 × 16 = 64.

class CausalSelfAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        assert d_model % n_heads == 0
        self.n_heads = n_heads
        self.head_dim = d_model // n_heads
        self.W_q = nn.Linear(d_model, d_model, bias=False)
        self.W_k = nn.Linear(d_model, d_model, bias=False)
        self.W_v = nn.Linear(d_model, d_model, bias=False)
        self.W_o = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x):                       # x: (B, T, d_model)
        B, T, d = x.shape
        # (B, T, d) -> (B, n_heads, T, head_dim)
        q = self.W_q(x).view(B, T, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.W_k(x).view(B, T, self.n_heads, self.head_dim).transpose(1, 2)
        v = self.W_v(x).view(B, T, self.n_heads, self.head_dim).transpose(1, 2)

        scores = q @ k.transpose(-2, -1) / self.head_dim**0.5   # (B, H, T, T)
        mask = torch.triu(torch.ones(T, T, dtype=torch.bool), diagonal=1)
        scores = scores.masked_fill(mask, float("-inf"))
        weights = F.softmax(scores, dim=-1)                     # (B, H, T, T)

        out = weights @ v                                       # (B, H, T, head_dim)
        out = out.transpose(1, 2).reshape(B, T, d)
        return self.W_o(out)

The forward pass reads as five moves: project the input three ways, reshape so heads become a batch dimension, compute the (T, T) score matrix per head, mask the upper triangle so position t only sees positions up to t, and average the values with the softmaxed weights. We spell out the score matrix explicitly rather than calling a fused kernel, because that (B, H, T, T) tensor is the object whose cost the next chapter is entirely about.4
4 Production code would call F.scaled_dot_product_attention, which fuses these steps and avoids materializing the full score matrix. We keep the explicit version so every intermediate is inspectable; the arithmetic is identical.

The MLP and the assembled block

The second sublayer is a two-layer network applied at every position independently: expand from 64 to 256 dimensions, apply a GELU nonlinearity, project back down. The 4× expansion is our choice for the miniature; K3's single dense MLP (layer 0) expands 7,168 to an intermediate_size of 33,792, a ratio of about 4.7×, and every other layer replaces this sublayer with a mixture of experts we build in Part 05.

class MLP(nn.Module):
    def __init__(self, d_model, d_hidden):
        super().__init__()
        self.up = nn.Linear(d_model, d_hidden, bias=False)
        self.down = nn.Linear(d_hidden, d_model, bias=False)

    def forward(self, x):
        return self.down(F.gelu(self.up(x)))

class TransformerBlock(nn.Module):
    def __init__(self, d_model=64, n_heads=4, d_hidden=256):
        super().__init__()
        self.norm1 = RMSNorm(d_model)
        self.attn = CausalSelfAttention(d_model, n_heads)
        self.norm2 = RMSNorm(d_model)
        self.mlp = MLP(d_model, d_hidden)

    def forward(self, x):
        x = x + self.attn(self.norm1(x))    # pre-norm residual
        x = x + self.mlp(self.norm2(x))
        return x

The block's forward is two lines, and both follow the same template: x = x + sublayer(norm(x)). Everything K3 does to this block happens inside sublayer; the template survives all of it.

Shape check and sanity checks

A forward pass at mini-K3 dimensions, with a parameter count:

block = TransformerBlock()
x = torch.randn(2, 10, 64)                  # batch 2, 10 tokens
print(block(x).shape)
print(sum(p.numel() for p in block.parameters()))
torch.Size([2, 10, 64])
49280

Shape in equals shape out, which is what lets blocks stack: our miniature will chain 8 of these (with substitutions), K3 chains 93. The 49,280 parameters split into 16,384 for attention (four 64×64 projections), 32,768 for the MLP (64×256 up and 256×64 down), and 128 for the two norms — the MLP carries about twice the parameters of attention, a ratio that MoE will later push much further.

One more check is worth the four lines it costs, because a silent masking bug is the classic way this module goes wrong. If the causal mask works, perturbing a late token must leave earlier outputs untouched:

x2 = x.clone()
x2[:, 7, :] += 100.0                        # perturb token 7 only
y1, y2 = block(x), block(x2)
print(torch.allclose(y1[:, :7], y2[:, :7], atol=1e-5))
print(torch.allclose(y1[:, 7:], y2[:, 7:], atol=1e-5))
True
False

Positions 0 through 6 are bit-for-bit unaffected by a large change at position 7, while positions 7 onward move. Information flows strictly left to right. We will rerun exactly this test on every attention replacement we build, because KDA's recurrence and MLA's compressed cache must both preserve this property.

What K3 keeps and what it replaces

Holding this block next to K3's config makes the rest of the book's itinerary concrete. The normalization survives unchanged: RMSNorm with rms_norm_eps 1e-5, applied pre-norm, exactly as implemented above. The residual template survives, though Part 04 adds a second, cross-depth pathway beside it. The attention sublayer is replaced everywhere: 69 layers get Kimi Delta Attention, which deletes the (T, T) score matrix in favor of a fixed-size recurrent state, and 24 layers get Gated MLA, which keeps the score matrix but compresses what gets cached. The MLP survives only in layer 0; layers 1 through 92 replace it with 896 routed experts of which 16 fire per token.

What survives from the baseline into K3: the skeleton and the norms. Both sublayers are substituted, and those substitutions are the subject of Parts 02 through 05.

As the figure shows, nothing about K3 requires unlearning this chapter — the baseline is not discarded but edited. The immediate question is why the attention sublayer, in particular, cannot be left alone. Our toy forward pass ran 10 tokens through a (10, 10) score matrix without noticing the cost. K3 is specified to run 1,048,576 tokens. In the next chapter we take the block we just built, put real numbers on what its attention would cost at that length — the score matrix's compute and, above all, the KV cache's memory — and find out exactly how many gigabytes force the redesign.
